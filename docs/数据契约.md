# 数据与业务契约

同一 learner 可以有多个 registration；每条 visit 是某次报名的一次课。现有 completed/eligible 是报名项口径，单课程接口保持此定义。directions 与 campuses 均可多值，不能将联接产生的副本视为不同事实。

## 数据集合

- `courses`：主键为 `course`；必填字段 `course, directions, campuses, term`，当前 4 条。
- `registrations`：主键为 `registration`；必填字段 `registration, learner, course, eligible, status`，当前 40 条。
- `visits`：主键为 `visit`；必填字段 `visit, registration, session, present`，当前 160 条。
- `completions`：主键为 `registration`；必填字段 `registration, completed`，当前 32 条。
- `definitions`：主键为 `metric`；必填字段 `metric, label, unit`，包含单课程与多维范围两类口径。
- `views`：主键为 `view`；必填字段 `view, course, recipient, cadence`，当前 1 条（旧单课程订阅）。
- `term_status`：主键为 `term`；必填字段 `term, status`，status 取值 `active/closed`，每个开课学期必须有一条。
- `course_owners`：主键为 `(course, owner)`；同一门跨校合办课程可挂多个 owner，各 owner 只承担该课程的共有责任。

集合中的主键不得重复；schema 的 foreign 引用须指向已存在的记录。可空字段保留 null 的业务含义，不自动补零。

## 统一指标口径（learner-scope-v1）

多维视图、目标判定与转办共用 `app/metrics.py` 的同一份口径，口径版本号写入每个结果的 `basis.caliber_version`，并附 `dataset_fingerprint`、范围过滤器、命中课程与学期状态。数据或学期状态变化后，指纹变化，旧材料仍保留冻结依据，可与当前依据对照。

范围由方向、校区、学期过滤器组合确定（逗号分隔的单值参数，例如 `directions=photo,digital`），同一查询即可查看任意组合：

- `registered_people` / `participant_people` / `eligible_people` / `completed_people` 均为**学员去重**口径：同一学员在所选范围内只算一次，课程多方向归属、跨班学习不会让人数超过全校人数。
- `attendance_events` 是**课次**口径，可以累加；按方向/校区分组时，多归属课程的课次会在每个相关组各计一次，范围总数以 `total` 为准。
- 学员完成率 `learner_completion_fraction = completed_people / eligible_people`：分母是在范围内**已有结课资格**的去重学员，分子是其中**至少完成一门符合资格且确已完成的课程**的去重学员。绝不算各班比例再平均。
- 分组小计是各组内的去重学员数，**各格不相加等于总计**。`overlap` 块列出同时进入多个组的学员与多归属课程并给出说明；`detail=true` 时返回学员名单与每门课明细，`total=false` 只看分组。
- 没有结课资格学员（分母为 0）时完成率为 `null`，且不触发低完成率催办。

## 查询与材料

GET 查询使用 UTF-8 JSON，错误参数返回 400，不存在的接口返回 404。重复的单值参数视为无效。summary 与 HTTP 调用同一组只读计算，材料包含数据内容指纹，便于核对输入。

- `/api/metrics`：统一口径多维查询，参数 `directions, campuses, terms, group_by(direction/campus/term/course), detail, total`。
- `/api/saved_views`：列出已保存的订阅定义。临时展开（detail、分组切换）只是只读查询，不会写成订阅定义。
- 订阅定义通过工作流 `views.save` 持久化到本地业务日志，只保存范围、分组、收件人与节奏；同一 view 名重复保存返回错误。

## 办理协作（同一范围）

旧的单课程流程 `targets.evaluate → followups.assign → followups.close → deliveries.prepare` 保持不变。新增范围流程与多维视图共用同一口径与同一份过滤器：

- `targets.evaluate_scope`：按订阅定义的范围判定，目标取范围内各课程 `minimum` 的最严值；未达目标时 `affected_people` 只列有结课资格但未完成的学员。
- 问题标识 `problem_key` 仅由范围过滤器哈希生成，**不含分组方式**。换个分组重新判定仍是同一问题，已办结的跟进单不会再次催同一批人。
- `followups.assign_scope`：按 `course_owners` 为每个责任校区生成一张工单（`case = problem_key:owner`）。跨校合办课程的各校区工单标记 `responsibility=shared`，且 `scope_courses` 只含本校区承担的课程，任何一方都不会把整个范围当成自己的全部责任。重复分派幂等，关闭后再分派保持 closed。
- `deliveries.prepare_scope`：周材料同时携带冻结依据 `frozen_basis` 与当前依据 `current_basis`；指纹不一致时 `basis_current=false` 并提示按旧依据阅读。待发跟进单只列当前仍成立（目标仍未达、依据未变、学期未关闭）的 open 工单；学期关闭后不再产生待发催办。

每个操作在本地业务日志的事务中更新；失败不提交半条办理记录。接口传入业务标识，未知标识或不满足条件返回错误，不自动补建对象。
